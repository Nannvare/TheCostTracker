    <h1>RM Master — Quick User Guide (Compact Version)</h1>
    <p class="lead">A compact, task-oriented version of the RM Master manual — ideal for daily users and testers who need quick instructions and common troubleshooting steps.</p>

    <div class="grid">
      <div>
        <h2>At-a-glance</h2>
        <div class="panel">
          <strong>Purpose:</strong> Manage raw material lookup data used by pricing, packing and procurement flows.
          <ul>
            <li><strong>Add / Edit / Delete</strong> RM records.</li>
            <li><strong>View API history</strong> to confirm upstream integrations.</li>
            <li>Units, purity flag and category directly impact price/packing processing.</li>
          </ul>
        </div>

        <h2>Quick actions</h2>
        <ol class="steps">
          <li><strong>Add</strong> — Select Category & Unit, type RM Name, check <em>IsPurity</em> if needed, click <span class="kbd">Add</span>.</li>
          <li><strong>Edit</strong> — Click <span class="pill">Edit</span> on row → update form → click <span class="kbd">Add</span> to save.</li>
          <li><strong>Delete</strong> — Click <span class="pill">Delete</span> → confirm. System may block deletion if referenced.</li>
        </ol>

        <h2>Search & Pagination</h2>
        <p class="muted">Use the search box to filter by name/category/unit. Page controls at the bottom allow fast navigation for large catalogs.</p>

        <h2>API History — common scenarios</h2>
        <table>
          <thead><tr><th>Scenario</th><th>What to do</th></tr></thead>
          <tbody>
            <tr><td><strong>Processed successfully</strong></td><td>Record accepted by API. No action required.</td></tr>
            <tr><td><strong>Pending (Not Processed)</strong></td><td>Check the Processing Remarks for error details; fix source data and reprocess.</td></tr>
            <tr><td><strong>Invalid Unit</strong></td><td>Open unit master, correct code and requeue record.</td></tr>
            <tr><td><strong>Not Exists</strong></td><td>Create referenced packing/material first or correct PrimaryId reference.</td></tr>
          </tbody>
        </table>

        <h2>Top 6 Test cases (smoke)</h2>
        <ol>
          <li>Create RM with minimum fields — expect success and API log entry.</li>
          <li>Create duplicate RM name — system should warn or prevent duplicate.</li>
          <li>Set IsPurity and leave purity blank — check API history for "Pending" remark.</li>
          <li>Edit unit to unsupported value — expect API remark "Measurement Unit is Invalid".</li>
          <li>Delete RM used by Price Master — verify block or appropriate error message.</li>
          <li>Filter API History by Status = Pending and confirm the returned rows match expected errors.</li>
        </ol>
      </div>

      <aside>
        <h2>Quick reference</h2>
        <div class="panel">
          <strong>Field checklist</strong>
          <ul>
            <li>RM Category — required</li>
            <li>Measurement Unit — required</li>
            <li>RM Name — required, unique per category recommended</li>
            <li>IsPurity Required — optional; affects downstream validation</li>
          </ul>
        </div>

        <h2>Common API remarks</h2>
        <div class="panel">
          <ul>
            <li><strong>Processed successfully.</strong></li>
            <li><strong>Packing Material not Exists</strong> — create packing item first.</li>
            <li><strong>Packing Material Measurement Unit is Invalid</strong> — correct measurement unit code.</li>
            <li><strong>Packing Material not Exists / not Exists</strong> — check primary id mapping.</li>
          </ul>
        </div>

        <h2>Troubleshooting flow</h2>
        <ol>
          <li>Open API History → set Transaction Type → filter by Status = Pending.</li>
          <li>Read Processing Remarks; note PrimaryId values.</li>
          <li>Fix source record (create missing item or correct unit), then reprocess.
          </li>
        </ol>

        <h2>Useful tips</h2>
        <ul>
          <li>Keep unit codes consistent between systems.</li>
          <li>Use a naming standard to avoid duplicates.</li>
          <li>When importing, preview API History to catch errors early.</li>
        </ul>
      </aside>
    </div>

    <h2>Printable checklist</h2>
    <div class="panel">
      <ul>
        <li>[ ] RM Name present</li>
        <li>[ ] Category selected</li>
        <li>[ ] Valid Measurement Unit</li>
        <li>[ ] IsPurity set when required</li>
        <li>[ ] No duplicates in table</li>
      </ul>
