The API Transaction History is a crucial module   
  designed to track and monitor all data
  synchronization attempts from external APIs into  
  TheCostTracker system. It provides a detailed log 
  of every transaction, including those for Raw     
  Material Master, Packing Material Master, Raw     
  Material Price Master, and Packing Material Price 
  Master.

  Purpose:
   * Monitoring Data Integration: It allows users to     confirm that data being sent from external     
     systems is successfully received and processed 
     by TheCostTracker.
   * Verification: Users can verify whether specific     records (like new raw materials or updated     
     prices) have been successfully created or      
     modified within the system.
   * Troubleshooting: It acts as a primary tool for 
     diagnosing and resolving issues when data      
     synchronization fails.

  Key Information Provided:
  For each transaction, the history typically       
  displays:
   * Transaction Type: Identifies the type of master     data being processed (e.g., Raw Material       
     Master, Packing Material Price Master).        
   * Status: Indicates if the transaction was       
     "Processed successfully" or "Not Processed."   
   * Processing Remarks: This is a vital field that 
     provides specific error messages or reasons for     transaction failures (e.g., "Packing Material  
     Measurement Unit is invalid," "Packing Material     not Exists").
   * IDs (PrimaryId1, PrimaryId2): References to the     source records.
   * Processing Time: The timestamp of when the     
     transaction was processed.

  How it Works (Troubleshooting Flow):
  When data synchronization issues arise, users can:   1. Access the API History page (from the relevant      master screen, like RM Master or PM RM Master,      by clicking the "API History" button).        
   2. Filter transactions by "Status" to identify   
      those that are "Pending/Not Processed."       
   3. Examine the "Processing Remarks" for each     
      failed transaction to understand the cause of 
      the error.
   4. Use the details from the remarks to correct   
      the original source data or address any       
      missing dependencies (e.g., creating a missing      packing material) in TheCostTracker.
   5. After corrections, the system expects these   
      records to be reprocessed successfully in     
      subsequent API calls.
